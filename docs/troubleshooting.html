Troubleshooting

Most problems are a missing model, a busy port, or a platform library. Start with the symptom table, then run the diagnostics command it points to.

Updated 2 November 2026 6 min read

Most problems are a missing model, a busy port, or a platform library. Start with the symptom table, then run the diagnostics command it points to.

First: read the health report#

lfm3 doctor --probe-models

On Windows, run it from the install folder or through a source checkout with cargo run -p lfm3-cli -- doctor --probe-models. It reports the resolved runtime path, every model endpoint and the identity it serves, the models folder, the workspace, and every missing item.

Models and downloads#

A download fails or never finishes. Only one role downloads at a time. Cancel the active one before starting another. A failed verification discards the .part file; retry the download rather than reusing it. Check free disk space — all four roles need about 4.9 GB.

The SHA-256 check fails. The file arrived corrupt or was modified in transit. Delete the .part file and download again. Do not rename a partial file into place: the digest is the identity of the weight.

You copied weights in by hand. Keep the repository subfolder layout, then choose Reload installed models. The app verifies byte length and SHA-256; a mismatched file is reported rather than used.

The models folder is on another drive. Set LFM3_MODELS_DIR to that folder, or set models_dir in setup.json. Use an absolute path; a relative path is not resolved against your shell's working directory.

Ports#

The four roles use 8080, 8081, 8082, and 8083 on loopback. If another tool holds one, the role cannot start.

Linux

ss -lntp | grep -E ':(8080|8081|8082|8083)'

Windows (PowerShell)

Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 8080,8081,8082,8083 |
  Select-Object LocalAddress, LocalPort, OwningProcess

Either stop the other process, or point the role at another loopback port with LFM3_TEXT_URL (and the matching *_URL variable). If you already run your own llama-server, --external lets the CLI reuse it instead of owning one.

Platform issues#

Windows#

  • SmartScreen. The installers are unsigned. Verify the checksum from the Install page, then choose More info → Run anyway. There is no certificate to look for and no way to make the dialog disappear without signing the build.
  • Installed to a path with a space. That is by design (%LOCALAPPDATA%\LFM3 Workspace) and exercised by the project's own smoke test.
  • Missing VC++ DLLs. The bundle includes vcruntime140.dll, vcruntime140_1.dll, and msvcp140.dll. If a repair removed them, reinstall.

Linux#

  • WebKitGTK errors on launch. Install the development and runtime packages for WebKitGTK 4.1 and GTK 3; run.sh deps prints the exact command for your distribution.
  • AppImage will not start. If FUSE is missing, extract and run:
./LFM3.Workspace_0.1.1_amd64.AppImage --appimage-extract
./squashfs-root/AppRun
  • A system libllama conflicts. Packaged libraries are already first in LD_LIBRARY_PATH for owned processes. If you run your own server, keep its libraries and the bundled ones on separate paths.
  • No system voice. Linux has no SAPI equivalent, so an incomplete voice pair means speech output is reported unavailable rather than silently substituting a different voice.

Voice#

ProblemCheck
Microphone button does nothingOS microphone permission for the app
"Voice model unavailable"Audio GGUF and its mmproj are both installed
Transcript is emptyThe clip was silent; the harness refuses an empty recording rather than inventing text
Speech output uses a robotic voice on WindowsThat is the offline system voice, labelled system-sapi; install the voice pair for the local model
Speech output fails on Linuxllama-tts is missing or the voice pair is incomplete

The local audio model transcribes verbatim. It does not label speakers or add timestamps, so a transcript without them is correct behaviour, not a bug.

Chat behaviour that looks like a bug#

  • A second message is refused while a turn is live. One bounded turn at a time is deliberate; the error is visible rather than queued.
  • The turn stops by itself. A turn allows at most twelve tool rounds. Ask for the next step.
  • A write is missing its approval card. The write gate may have held it. The gate chip under the conversation states the outcome; a hold means nothing was written and the model was told not to retry.
  • The model says it finished but the file is empty. Chat is not verified work. For a measured result, use Jobs or Verified tasks.
  • Routing picked the wrong intent. It selects capability hints only. Rephrase with an explicit verb and file name; a missing or low-confidence decision model falls back to keywords.

Jobs and verified runs#

StatusWhat to change
turn_budgetNarrow the goal or produce the output sooner; raising the cap on a vague goal usually repeats work
deadlineSame, plus a realistic minute budget
stalledThe loop saw three turns without a plan or six without a write; restate the goal with one concrete deliverable
unverifiedNo measurable artifact; name the required output path
interruptedThe engine stopped mid-run. It is never resumed; start a new job
incomplete / no_progressA verified run exhausted its retries without passing. Read the check evidence in the report

A verified mission with human_review_only cannot be started at all. That is the qualification gate, not a configuration problem; see Verified tasks.

Reset state#

Back up first. There is no migration between versions and no recovery for a deleted transcript.

WhatWhere
One conversationDelete it in the chat sidebar
All conversations and approvalschat.db in the data directory
Jobsjobs.db
Verified-run historyruns.db in the data directory
Workspace choiceworkspace in setup.json, or the folder chip
ModelsThe models folder

Removing the whole data directory returns the app to a fresh install while keeping your workspace files untouched.

What to include in a bug report#

  1. Version from the footer or the Models menu, and the platform.
  2. Output of lfm3 doctor --probe-models.
  3. The model states (Loaded / Installed / Missing) for all four roles.
  4. The exact error text, copied rather than paraphrased.
  5. The smallest workspace that reproduces it, and whether a fresh folder behaves the same.
  6. For a verified run: the run id, so the journal state can be read with lfm3 status <run-id>.

Reports that name the file path and say what was expected versus observed are the ones that get fixed.
