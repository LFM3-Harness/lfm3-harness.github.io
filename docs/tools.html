Tool reference

Tools are capabilities the harness grants per turn, not a plugin surface. Each one is bounded by the chosen folder, and the offered list is enforceable, not advisory.

Updated 2 November 2026 4 min read

Tools are capabilities the harness grants per turn, not a plugin surface. Every path is checked against the workspace by the same resolver that verified missions use, and the offered list is enforced rather than advisory: a tool that was not granted is refused before any path resolution or side effect.

Grant rules#

ContextWhat is granted
Chatlist_files, read_file, search_files, related_files, write_file, edit_file
Chat, vision installedAdds look
Chat, audio installedAdds transcribe
Job loopsearch_files and related_files always; look and transcribe only when the route selects their model; narrows to write_file once every source is read
Verified missionExactly the tools listed in its manifest, still path-confined

Chat has no shell tool, and no configuration adds one. General tasks cannot author a shell command either.

File tools#

list_files#

Maps a directory tree. Arguments: an optional path (defaults to the workspace root).

  • Directory walking stops at depth 4 and at 500 entries, appending a truncation marker.
  • target, .git, node_modules, and .svn are skipped.
  • Output is clipped at 32,000 characters.

read_file#

Opens one text file. Arguments: path.

  • Files above 1 MiB are refused with the limit in the error, rather than read partially.
  • Output is clipped at 32,000 characters.
  • Only files inside the workspace, with no link or reparse point anywhere in the path, are readable.

write_file#

Creates or replaces a file. Arguments: path, content.

  • Requires approval in chat; a job's write guards also refuse empty or placeholder content.
  • Content is limited to 1 MiB.
  • Missing parent directories are created, so out/report.md works in a fresh folder.
  • The write is atomic, and the tool returns the byte length and digest of what it wrote.

edit_file#

Replaces one exact occurrence. Arguments: path, old_text, new_text.

  • old_text must be non-empty and must occur exactly once; zero or multiple matches are errors, not guesses.
  • New content is limited to 1 MiB and the result is written atomically.
  • Requires approval in chat.

Search tools#

search_files#

Matches names and text across the workspace without a shell. Arguments: query, optional path, optional max_results (default 20, clamped to 1–40).

  • Walks at most 4,000 entries to depth 10 and skips target, .git, node_modules, .svn, dist, and .lfm3.
  • Each file is scanned up to 512 KiB; snippets are 160 characters, up to three per file.
  • Every hit reports how many matches were found and how many were shown.

related_files#

Compares one file's distinctive terms with the other text files. Arguments: path, optional max_results (default 10, clamped to 1–30).

  • Common stop words are removed so the comparison keys on distinguishing terms.
  • Use it to answer "what else belongs with this file?" without the model guessing from filenames.

Sense tools#

look#

Inspects one image through the local vision model. Arguments: path, instruction.

  • PNG, JPEG, WebP, and GIF are supported.
  • The harness prepends measured facts: format, byte length, and pixel dimensions.
  • The model observes one image at a time and never receives the planning loop.
  • Requires the vision role and its mmproj.

transcribe#

Returns verbatim text for one recording. Arguments: path.

  • WAV, MP3, FLAC, OGG, and M4A are supported.
  • The result includes measured container facts: duration, sample rate, and channel count.
  • It does not label speakers, add timestamps, or summarise; that is deliberate, because the model is not an analyst and inventing structure is worse than omitting it.
  • Requires the audio role and its mmproj.

speak#

Renders one answer as speech through llama-tts. Used by Speak and Voice replies, not offered to the acting model as a planning tool.

  • One 120-second watchdog guards the owned process.
  • The temporary WAV is deleted after it is returned.
  • Requires the audio role and its mmproj; Windows can fall back to the offline system voice labelled system-sapi.

Structural tools#

These are not file tools and do not touch disk.

ToolUsed byPurpose
todo_writeJob loopWrites the plan, one to eight steps, each with an optional deterministic check
finishJob loopEnds the job. Refused until the required output exists and is non-empty

todo_write is the plan gate: no workspace action is accepted before a non-empty plan exists, and a step that claims done is demoted when its check fails against the real workspace.

finish is the honesty gate: the report carries the measured byte length and a content digest recomputed from the file it re-read. A bare "finished" is refused.

Error behaviour#

Tool errors are returned to the model as real output, not hidden. That is what lets a small model correct itself:

ErrorCause
OutsideWorkspaceA path with .., an absolute path outside the root, or a canonical escape
ReparsePointA symbolic link, junction, or reparse point anywhere in the path
NotFound / NotAFile / NotADirectoryThe target does not match the requested access
NotGrantedThe tool was not offered this turn
Output limitThe file or directory exceeds a documented cap

A refused call that never executed does not count as an observation for later phases, so the model can still take the same action once the phase allows it.
