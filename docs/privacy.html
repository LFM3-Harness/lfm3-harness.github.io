Under the hood

Privacy, security, and licensing

Local-first is an engineering property here, not a slogan: loopback-only servers, no account, no runtime network calls, and three clearly named exceptions.

Updated 2 November 2026 5 min read

Local-first is an engineering property here, not a slogan: loopback-only servers, no account, no runtime network calls, and three clearly named exceptions.

What leaves your machine#

There are exactly three outbound paths, and two of them require you to act.

PathWhenWhat is sent
Model downloadYou click Download on one roleAn HTTPS request to huggingface.co/LiquidAI for a pinned file name
A link you clickYou click itWhatever that site normally receives
Opt-in tracingYou set POSTHOG_API_KEYModel-call metadata; prompt and completion text only if POSTHOG_AI_CAPTURE_CONTENT=1

The download host, file names, byte lengths, and SHA-256 digests are fixed in the source. There is no "check for updates", no crash reporter, no telemetry client when the key is unset, and no remote model endpoint.

What never leaves#

  • Prompts, model replies, and tool output.
  • The contents of any file in your workspace.
  • Images you attach, audio you record, or transcripts the audio model produces.
  • Chat transcripts, job records, and verified-run journals.
  • Your folder paths, machine name, or usage counts.

Speech recognition and speech synthesis both run on the local audio model. There is no cloud transcription path to disable, because there is none.

The network boundary, in code#

  • Every role's default endpoint is 127.0.0.1: :8080 text, :8081 vision, :8082 audio, :8083 decision.
  • Under LFM3_PROFILE=packaged the engine refuses to start if any endpoint is not loopback, or if LFM3_ALLOW_DOWNLOAD is on.
  • Boot-time discovery reads paths; it never contacts the network.
  • The installers contain no updater component.

You can verify the listener side yourself while the app is running:

Linux

ss -lntp | grep -E ':(8080|8081|8082|8083)'

Windows (PowerShell)

Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 8080,8081,8082,8083 |
  Select-Object LocalAddress, LocalPort, OwningProcess

Every row should show 127.0.0.1 or ::1, never 0.0.0.0.

Data at rest#

Everything the app knows lives in the trusted data directory:

ItemSensitivity
chat.dbFull conversation content
jobs.dbJob goals, turns, tool output
Run journalSteps, evidence, digests, prompts used by the judge
setup.jsonLocal absolute paths
models/Public model weights

The data directory is protected by your operating-system account permissions, and nothing more. There is no application-level encryption, no key management, and no password. If your threat model includes someone with your unlocked account or your disk, use full-disk encryption — that is the control that fits this design.

Attachments are copied into .attachments/ inside the workspace, not the data directory, so they travel with the folder you chose. Delete that folder to remove them.

The trust boundary#

The design assumption is that model output is untrusted.

ConcernControl
Model writes a file you did not wantExact diff, Allow once, ten-minute expiry, no blanket grant
Model reaches outside the folderOne shared path resolver; .., absolute escapes, and links refused
Model runs a commandNo shell tool in chat; missions cannot author shell commands
Model lies about finishingCompletion is re-derived from the filesystem; the digest is recomputed from the re-read file
Model contradicts your requestWrite gate hold at a 75% floor
Model guesses from thin evidenceEvidence gate note at 65% floor
Chat output counted as certified workSeparate surfaces, separate completion rules
A semantic judge invents a passGrounding checks first; human_review_only; automatic passing disabled
A crashed app leaves servers runningJob Object or process group containment, proven by smoke tests

What the gates are not: authority. A gate can withhold a mismatched change or ask for better evidence, and it can never approve, deny, or execute anything.

What is still yours to do#

The harness narrows what can happen. It does not take responsibility for your machine or your judgement:

  1. Review the diff. The approval exists because you are the reviewer. Approving without reading is the one control the harness cannot enforce.
  2. Choose the folder deliberately. Do not point it at a directory holding secrets you would not paste into a chat window.
  3. Keep the operating system trusted. An attacker with your account can read the data directory and the workspace.
  4. Check downloads you did not make in the app. A GGUF you copied in has your provenance, not the catalog's.
  5. Treat model claims as claims. A 1.7B model can be wrong confidently. Open the cited file when it matters.
  6. Encrypt the disk if the machine can be stolen.

Independence#

LFM3-Harness is an independent, community-built experimental application for running and exploring Liquid AI's LFM3 models locally. It is not affiliated with, endorsed by, or sponsored by Liquid AI, and it claims no rights in the LFM3 name or weights.

Reporting a problem#

Security issues belong in the repository's issue tracker unless they involve an undisclosed vulnerability, in which case contact the maintainer privately before publishing details. Include the version, platform, and the smallest reproduction you can build; a report that names a file path and an expected versus observed result is worth ten that describe a feeling.
