CLI reference

The same Rust engine the desktop app embeds, driven from a terminal. Useful for headless machines, scripted acceptance runs, and reading the journal directly.

Updated 2 November 2026 5 min read

The lfm3 CLI drives the same Rust engine the desktop app embeds. It is the right tool for a headless machine, a scripted acceptance run, or reading the journal directly.

In the Linux CLI archive the binary is lfm3-cli, and run.sh wraps it with the bundled runtime and models paths. In a source checkout, use cargo run -p lfm3-cli --. The commands below are written as lfm3 for brevity.

lfm3 doctor
lfm3 missions
lfm3 models --probe
lfm3 run --mission desk_task --input tests/fixtures/desk_task/basic.json --workspace tests/fixtures/desk_task/workspace

Global options#

OptionDefaultMeaning
--missions <dir>missionsDirectory of mission manifests
-h, --helpCommand help, including every flag
-V, --versionBinary version

Every command loads configuration from LFM3_* variables and validates it before doing anything else. A bad value fails fast with the constraint in the message.

doctor#

Reports the resolved configuration without loading a model.

OptionMeaning
--probe-modelsAlso probe the pinned llama.cpp runtime and each local model endpoint

Use it as the first diagnostic on any machine. It lists every missing path and the resolved workspace and models directory.

lfm3 doctor --probe-models

missions#

Lists validated mission manifests from the missions directory. A manifest that fails validation is reported, not silently skipped.

models#

Reports configured model endpoints and local weights.

OptionMeaning
--probeAsk each local endpoint for the model identity it serves

plan#

Drafts and validates a plan without creating a run.

OptionMeaning
--mission <name>Mission to plan for
--fixture <file>Acceptance fixture JSON (alias --input)
--goal <text>Goal text when no fixture is used
--workspace <dir>Workspace folder
--externalReuse an already-running loopback server
--startup-timeout <seconds>Model-server startup budget (default 120)
--fake-modelTest-only scripted model; excluded from packaged builds

run#

Plans, executes, verifies, retries, and reports one run.

OptionMeaning
--mission <name>Mission to run
--fixture <file>Acceptance fixture JSON (alias --input)
--goal <text>Goal text when no fixture is used
--workspace <dir>Workspace folder
--db <file>Journal database path
--events <target>- for stdout, or a file path
--timeout <seconds>Whole-run deadline
--externalReuse an already-running loopback server
--startup-timeout <seconds>Model-server startup budget (default 120)

run exits 0 only when every frozen step check and the final output contract pass. The report includes the acceptance hash, per-step attempts, check evidence, observed versus expected output digests, and the event journal count.

lfm3 run \
  --mission desk_task \
  --input tests/fixtures/desk_task/basic.json \
  --workspace tests/fixtures/desk_task/workspace \
  --events -

With --events -, durable JSON lines go to stdout and the human-readable report goes to stderr, so the two can be redirected independently.

status#

Shows the durable journal state of a run.

Argument / optionMeaning
[run]Run id; defaults to the most recently created run
--db <file>Journal database path
--eventsInclude the durable event journal in the report

retry#

Creates a linked run with the same frozen acceptance contract.

Argument / optionMeaning
[run]Run id to retry; defaults to the most recent
--db <file>Journal database path
--workspace <dir>Workspace to reuse; required, because the journal stores no path
--events <target>- or a file path
--timeout <seconds>Whole-run deadline
--externalReuse an already-running loopback server
--startup-timeout <seconds>Model-server startup budget

The retry chain is recorded in the journal. A retry cannot weaken a check: the acceptance contract is the same one, frozen at the original run.

task#

The plan-first path: turns a stated goal into a frozen, verified plan without a pre-authored mission.

OptionDefaultMeaning
--goal <text>requiredWhat to accomplish
--deliverable <path>detectedRequired output, relative to the workspace
--planoffPrint the plan and execute nothing
--minutes <n>30Whole-task deadline; clamped to 1–1440
--steps <n>16Most steps the plan may contain; clamped to 1–32
--min-steps <n>2Fewest steps; a task must not collapse into one call
--workspace <dir>configWorkspace folder
--db <file>configJournal database path
--events <target>none- or a file path
--timeout <seconds>noneDeadline in seconds; overrides --minutes
--externaloffReuse an already-running loopback server
--startup-timeout <seconds>120Model-server startup budget
lfm3 task --goal "Summarise demo/notes.md into out/summary.md" --workspace ./demo
lfm3 task --goal "Summarise demo/notes.md into out/summary.md" --workspace ./demo --plan

Every step must declare at least one check. A write_file or edit_file step whose checks name no path is rejected before the acceptance is frozen, so an untestable step never runs.

job#

Runs a stated job as an agent loop until its required output verifies.

OptionDefaultMeaning
--goal <text>requiredWhat to accomplish
--deliverable <path>detectedRequired output, relative to the workspace
--workspace <dir>configWorkspace folder
--minutes <n>30Whole-job budget; clamped to 1–1440
--max-turns <n>40Most model turns before the loop stops
--max-calls <n>3Tool calls accepted per turn; clamped to 1–4
--events <target>noneJSON-lines trace: - or a file path
--timeout <seconds>noneDeadline in seconds; overrides --minutes
--externaloffReuse an already-running loopback server
--startup-timeout <seconds>120Model-server startup budget
lfm3 job --goal "Read notes/ and write out/report.md, one section per note" \
  --workspace ./demo --minutes 30 --events -

The loop's statuses are passed, unverified, turn_budget, deadline, and stalled; see Jobs for what each one means and how the plan, work, and review phases behave.

Exit codes#

CodeMeaning
0The run passed: every frozen check and the output contract
1No pass: incomplete, a refusal, a configuration error, or an unavailable model

There is no code for "probably fine". A run that cannot certify its output exits non-zero, and the report says why.

Event stream#

--events - writes durable JSON lines to stdout; --events <file> appends to a file. Each line is one durable event from the run: attempt starts, step failures, retries, checks, and the final status.

The desktop app uses the same event model over Tauri channels (lfm3:run-event, lfm3:job-event, lfm3:chat-event). The journal is the source of truth; the stream is a live view of it.

Reproducible acceptance#

scripts/release-real-model.ps1 drives the optimized CLI against the pinned models and writes a report, an event journal, a stderr capture, and a result JSON per case into tests/golden/release/. The eight cases it covers (success, failure, escape, retry, crash, unavailable, timeout, missing) are listed in Verified tasks.

scripts/accept.ps1 runs the full release gate: formatting, clippy with warnings denied, workspace tests, the no-Python check, UI typecheck and unit tests, Playwright, the NSIS build, and the installed smoke acceptance. See Build from source.
