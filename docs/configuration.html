Configuration

Configuration is read from the environment first and setup.json second. Discovery is read-only: boot never downloads, copies, or contacts a network.

Updated 2 November 2026 3 min read

Configuration is read from the environment first and setup.json second. Discovery is read-only: boot never downloads, copies, or contacts a network.

Run lfm3 doctor after any change. It prints the resolved values, every missing path, and the workspace and models directory the engine will actually use.

Precedence#

LayerWhat it setsWins over
Environment variablesEverything, including endpoints and limitssetup.json
setup.jsonRuntime paths, models folder, default workspaceBuilt-in discovery
Bundled resourcesLFM3_LLAMA_SERVER and LFM3_LLAMA_TTS defaults from the packageBuilt-in discovery only; never a path you set

The desktop shell seeds runtime paths from its own resource directory so an installed package resolves its bundled llama.cpp exactly like a source checkout. A path you set yourself is never replaced.

Data directory#

PlatformDefault
Windows%LOCALAPPDATA%\LFM3Harness, falling back to %USERPROFILE%\AppData\Local when LOCALAPPDATA is missing
Linux$XDG_DATA_HOME/LFM3Harness, or ~/.local/share/LFM3Harness when unset

It holds setup.json, chat.db, jobs.db, the verified-run journal, and the models folder. Override with LFM3_DATA_DIR.

Core#

VariableDefaultMeaning

LFM3_REUSE_EXTERNAL_SERVERSfalseReuse an already-running loopback server instead of owning one

Runtime paths#

VariableMeaning
LFM3_LLAMA_SERVERPinned b11960 / v0.8.0 llama-server (llama-server.exe on Windows)
LFM3_LLAMA_TTSllama-tts for local speech output
LLAMA_CACHEllama.cpp cache directory, when you want to pin one

The runtime must report build 11960 and release 0.8.0 to be accepted as pinned. Only then does the UI show verified pin.

Limits#

These are the durable run budgets. Values outside the stated range are refused at startup with the constraint in the error, not silently clamped.

VariableDefaultRange
LFM3_MAX_STEPS81–32
LFM3_MAX_ATTEMPTS_PER_STRATEGY31–8
LFM3_MAX_STRATEGIES21–4
LFM3_MAX_TOTAL_ATTEMPTS6At least one strategy, at most 16
LFM3_RUN_TIMEOUT_SECONDS90010–86400
LFM3_MAX_TOKENS4096128–32768
LFM3_TEMPERATURE0.10–2, finite
LFM3_SHELL_TIMEOUT1201–3600
LFM3_CONTEXT_CHARS180001,000–1,000,000

Which limits the executor honours

The executor uses its built-in 512-token cap per step and the planner a fixed 1,536. limits.max_tokens is a configuration surface that is not yet wired into those requests; the project tracks this as a known gap rather than pretending it applies.

Tracing#

VariableDefaultMeaning
POSTHOG_API_KEYemptyEnables opt-in PostHog AI tracing of local model calls. Empty means no client and no outbound request
POSTHOG_AI_CAPTURE_CONTENTemptyWhen set to 1, prompt and completion text is attached to a trace

With the key unset, there is no tracing client at all. Metadata-only tracing is the default even when a key is present.

setup.json#

Write this file into the data directory to pin paths without environment variables. Every supplied path must be absolute and present; a malformed file is reported and left untouched.

{
  "llama_server": "F:\\lfm3\\tools\\llama\\llama-server.exe",
  "llama_tts": null,
  "models_dir": "F:\\lfm3\\models",
  "projector": null,
  "workspace": "F:\\lfm3\\demo"
}
FieldMeaning
llama_serverPath to the pinned llama-server
llama_ttsPath to llama-tts, or null
models_dirFolder containing the GGUF weights
projectorVision projector path, or null when it sits beside the weights
workspaceDefault workspace, written by the chat header folder picker

On Linux use absolute paths such as /home/you/lfm3/tools/llama/llama-server. LFM3_WORKSPACE still takes precedence over the saved workspace value.

The packaged profile#

LFM3_PROFILE=packaged is a startup refusal, not a preference. With it set, the engine refuses to start when:

  • a model endpoint is not a loopback address, or
  • LFM3_ALLOW_DOWNLOAD is on.

The release bundles use the CPU profile with -ngl 0. The gpu profile exists for a runtime you build and provision yourself; no GPU backend ships in any installer.

Files the app writes#

FileRole
setup.jsonRuntime paths, models folder, default workspace
chat.dbConversations, messages, pending and decided approvals
jobs.dbJob records and their turns
runs.dbVerified runs, steps, attempts, evidence, retries
models/Verified GGUF weights, one subfolder per repository

All of it is local SQLite and JSON in the data directory. Nothing is synced, and nothing is uploaded.
